# 적응형 기상 알고리즘 (Adaptive Wake-up Algorithm)

## 왜 이 알고리즘이 필요한가

고정된 시간에 알람을 맞추면 **깊은 수면(Deep Sleep) 도중 강제 기상**이 일어날 수 있습니다.
깊은 수면에서 갑자기 깨어나면 *수면 관성(Sleep Inertia)* — 심각한 인지 저하·극심한 피로감 — 이 최대 수십 분간 지속됩니다.

이 알고리즘은 사용자가 설정한 기상 목표 시간(base_wake_time) 직전의 탐색 창(window) 안에서,
수면의 깊이와 침실 환경 쾌적도를 평가해 **가장 깨어나기 좋은 최적의 시간**을 찾아 알람을 울립니다.

---

## 4요인 기상 환경 스코어링 알고리즘

기상 1시간 전, 자동 스케줄러가 과거 60분간의 **실시간 심박수(HR)**와 **침실 환경(IoT: 조도, 온도, 습도)** 데이터를 종합하여 쾌적도 점수(0~100)를 산출합니다.

점수가 높을수록 현재 얕은 수면 상태이거나 이미 기상하기 좋은 환경이라는 뜻이며, 더 이상 깊은 수면으로 빠지지 않도록 **탐색 창의 앞쪽(더 이른 시간)**에서 알람을 울립니다. 점수가 낮을수록 수면 환경이 좋지 않거나 깊은 수면 중이므로, 최대한 수면을 보장하기 위해 **탐색 창의 뒤쪽(목표 시간)**에서 알람을 울립니다.

---

## 평가 요소 및 가중치

총 4가지 요소가 기상 점수를 결정하며, 각각의 가중치가 적용됩니다.

| 요소 | 가중치 | 만점(100점) 기준 | 설명 |
|---|---|---|---|
| **심박수 (HR)** | **40%** | 최저 심박수 대비 +20bpm 상승 | 수면 깊이를 가장 직접적으로 반영. 기상 직전의 심박 상승은 얕은 수면 및 자연 기상 신호를 의미합니다. |
| **조도 (Lux)** | **25%** | 500 Lux 이상 | 코르티솔 및 멜라토닌 조절을 통한 강한 생체시계(Circadian Rhythm) 신호입니다. (인간의 빛 인식 특성을 고려해 로그 스케일로 환산) |
| **온도 (Temp)** | **20%** | 19.5°C | 수면 및 기상에 가장 최적화된 온도 범위(18~21°C). 1도 벗어날 때마다 10점 감점. |
| **습도 (Hum)** | **15%** | 50% | 수면 쾌적도를 보조하는 지표. 최적 범위(40~60%). 1% 벗어날 때마다 2점 감점. |

## 데이터 흐름 및 전체 처리 흐름

### 1. 스케줄러 트리거 (AlarmSchedulerTask)
매분 동작하는 스케줄러가 **기상 목표 시각(base_wake_time) 정확히 1시간 전**에 도달한 알람을 찾아 동적 알람 시간 재계산을 요청합니다.
> **참고:** 자정 경계(예: 00:30 알람)의 경우, 전날 23:30에 정상적으로 다음 날짜의 알람을 미리 조회해 처리합니다.

### 2. 센서 데이터 조회 (DynamicAlarmService)
스케줄러가 동작한 현재 시점(`now`)을 기준으로 **과거 60분** 동안의 심박수(`HeartRate`) 및 IoT 환경 데이터(`RealtimeMetric`)를 1분 단위로 조회합니다.
추가로 어젯밤 수면 중 기록된 최저 심박수(`sleepMinBpm`)를 기준으로 삼습니다. (없을 경우 기본값 55bpm 사용)

### 3. 분 단위 종합 점수 계산 (EnvironmentalWakeEvaluator)
1분 단위로 매칭된 HR과 IoT 데이터를 통해 `combinedScore`를 계산합니다.
- 심박 점수: `(bpm - 최저심박) / 20 * 100` (최대 100점)
- 조도 점수: `log10(lux + 1) / log10(501) * 100` (500 lux 이상 시 100점)
- 온도 점수: `100 - |temp - 19.5| * 10`
- 습도 점수: `100 - |hum - 50| * 2`
  
조회된 60분 전체 구간의 분 단위 점수들의 **평균(Average)**을 내어 최종 `aggregateScore`를 도출합니다.

### 4. 탐색 창(Window) 내 기상 시간 결정
- `ratio = (100 - aggregateScore) / 100`
- `dynamicWakeAt = windowStart + (windowMinutes * ratio)`

**예시 시나리오 (`baseWakeTime` = 07:30, `windowMinutes` = 30분):**
- **탐색 창:** `07:00 ~ 07:30`
- **점수 100점 (가장 이상적):** `ratio = 0` → **07:00 기상** (얕은 수면 중이므로 바로 기상)
- **점수 50점 (보통/데이터 없음):** `ratio = 0.5` → **07:15 기상**
- **점수 0점 (깊은 수면/최악의 환경):** `ratio = 1` → **07:30 기상** (수면 시간 최대한 보장)

### 5. 폴백 (Fallback) 메커니즘
스마트 워치 미착용 등 여러 변수에 대응하기 위한 폴백이 내장되어 있습니다.
- **HR 데이터가 없는 경우:** 심박수(40%) 가중치를 제외하고, 조도·온도·습도의 합산 가중치(60%)를 기준으로 100점 만점으로 정규화하여 평가합니다.
- **데이터가 전혀 없는 경우:** 중립 점수인 **50점**을 부여하여 탐색 창의 한가운데(중앙) 시간에 알람이 울리도록 처리합니다.

## 엣지 케이스 처리 로직

| 케이스 | 처리 결과 |
|---|---|
| 적응형 알람 설정 꺼짐 (`adaptive_enabled = false`) | 환경 데이터 무시하고 설정한 `base_wake_time` 정각에 울리도록 설정 |
| 알람 시간이 이미 지나버린 경우 | 다음 주 동일 요일의 `base_wake_time`으로 스케줄링 연기 |
| 데이터 전혀 없음 | 점수 50점으로 처리되어 탐색 창의 정확히 중간 지점 폴백 |
| 자정 직후(00:xx) 알람 | 전날 23:xx 에 스케줄러가 정상적으로 날짜(Day)를 보정하여 계산 수행 |

## 관련 소스 파일

| 파일 | 역할 |
|---|---|
| `service/DynamicAlarmService.java` | 1시간 전 과거 60분 센서 데이터 조회 및 최종 알람 시간 계산, 자정 날짜 계산 보정 |
| `util/EnvironmentalWakeEvaluator.java` | 4요인(HR, Lux, Temp, Hum) 수치에 대한 1분 단위 스코어링 공식 및 가중치 합산 |
| `service/AlarmSchedulerTask.java` | 매분 실행되며 1시간 뒤 울릴 알람 타겟을 탐색해 재계산 트리거 (자정 경계 요일 계산 포함) |
| `service/AlarmService.java` | 수동 알람 조회/변경 시 동적 알람 재계산 처리 |
